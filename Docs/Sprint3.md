# Sprint 3 — 랜덤 아티팩트와 탐험 빌드

[Sprint 1: 전투·조작](Sprint1.md) · [Sprint 2: 탐험 진행](Sprint2.md)

기존 `Sprint02-03.md`에서 아티팩트 정의·효과·보상 후보 생성·탐험 빌드를 분리했다. [Sprint 2](Sprint2.md)의 라운드 완료·보상 상태·세션 종료 흐름에 연결하며, 강화는 탐험 범위에서만 유지한다. Unity 2022.3.62f3 로컬 싱글 플레이 기준이다.

## 1. 목표와 구조

플레이어가 라운드 보상으로 무작위 아티팩트를 선택하고, 보유 조합에 따라 능력치·공격 효과가 달라지며, 탐험 종료 후 임시 강화가 제거되는 구조다. 기존 이동·공격·회피 코어를 대체하지 않고 필요한 전투 이벤트와 공격 스냅샷을 연결한다.

| 경계 | 파일과 역할 |
| --- | --- |
| 아티팩트 정의 | `Assets/Scripts/Artifacts/ArtifactDefinition.cs`: ID·이름·설명·아이콘·등급·가중치·중복 정책·최대 중첩·효과·태그 |
| 카탈로그 | `Assets/Scripts/Artifacts/ArtifactCatalog.cs`: 보상 대상 아티팩트 목록 |
| 후보 생성 | `Assets/Scripts/Artifacts/ArtifactRewardGenerator.cs`: 주입받은 System.Random으로 획득 가능한 후보를 가중치 추첨 |
| 플레이어별 빌드 | `Assets/Scripts/Artifacts/RunBuild.cs`: 개별 보유·중첩, 임시 보정, 공격 스냅샷, 확률 효과·회피 충전·동료 조건 |
| 데이터 에셋 | `Assets/Data/Expedition/Artifacts/**`, `ArtifactCatalog.asset`, 라운드의 보상 테이블 ID |
| 세션 연결 | 기존 ExpeditionManager의 보상 후보·선택·종료 명령과 ExpeditionSession의 보상 기록 |
| 표시 | 기존 ExpeditionUI와 ExpeditionUIView/ExpeditionChoiceView의 3개 보상 카드·보유 목록·능력치·발동 메시지 |
| 샘플 연결 | `Assets/Editor/ExpeditionSetup.cs` |
| 검증 | `Assets/Tests/Editor/Sprint03ArtifactTests.cs` |

현재 필요한 효과 유형을 작게 정의해 데이터를 추가할 때 아티팩트마다 별도 C# 클래스를 만들지 않아도 된다. 임의 효과를 해석하는 대규모 범용 인터프리터는 구현하지 않았다.

## 2. 전투 코드의 최소 연결

경로는 `Bottle Game/Assets/Scripts` 기준이다.

- `Player/PlayerStats.cs`: 기본 attackDamage/maxHealth를 유지하고 EffectiveAttackDamage/EffectiveMaxHealth로 탐험 보정을 조회한다.
- `Player/Gun.cs`, `Bullet.cs`, `FistHitbox.cs`: 공격 시작 당시의 효과 스냅샷을 전달·사용한다.
- `Player/PlayerAttackController.cs`, `NeckEffectController.cs`: 공격 속도 보정을 기존 실행·연출에 적용한다. 펀치의 뻗기·유지·회수를 같은 비율로 조정한다.
- `Player/PlayerDodgeController.cs`: 회피 이벤트와 세션 재시작 시 쿨다운 초기화를 연결한다.
- `Player/PlayerAutoTarget.cs`: 사거리 보정을 반영한다. 표시와 실제 타겟 탐색은 같은 유효 사거리를 사용한다.

총 발사·펀치 방향 고정·전체 회수·레거시 조작에 대한 최종 동작은 [Sprint 1](Sprint1.md)을 기준으로 한다.

## 3. 초기 아티팩트 12종

| 아티팩트 | 현재 실제 효과 | 최대 중첩 |
|---|---|---:|
| 녹슨 톱니 | 기본 공격력 +15% | 3 |
| 압축 스프링 | 공격 속도 +15%, 펀치 발사·유지·회수 전체를 같은 비율로 조정 | 3 |
| 깨진 병뚜껑 | 회피 개시 후 다음 공격 +60%, 한 공격에만 사용, 재회피는 충전을 추가 적립하지 않음 | 2 |
| 탄산 과충전기 | 탄환 피해 +12%. 현재 액체 시스템을 대신하는 명시적 탄환 강화 | 3 |
| 두꺼운 유리 | 최대 HP +25. 획득 자체는 회복하지 않음 | 3 |
| 폐건전지 | 탄환 적중 시 20% 확률로 탄환 피해의 35% 추가 타격, 재귀 발동 없음 | 3 |
| 고철 관통탄 | 적 한 명 추가 관통. 동일 적의 여러 콜라이더는 한 번만 타격 | 2 |
| 비상 밸브 | HP 35% 이하에서 받는 피해 -30%, 공격 속도 +25% | 2 |
| 정밀 노즐 | 탄환 수명과 자동 조준 사거리 +25%, 탄환 속도 유지 | 3 |
| 불안정한 압력통 | 공격력 +30%, 받는 피해 +20% | 3 |
| 우정의 빨대 | 3유닛 안에 생존한 탐험 동료가 있으면 공격력 +20%. 싱글에서는 비활성이라고 표시 | 1 |
| 재활용 증폭기 | 금속 태그의 보유 중첩 수마다 공격력 +4% | 2 |

같은 보정 종류는 중첩 수에 비례해 합산한다. 공격 속도·사거리 배율은 0.1–5로 제한한다. 저체력 감소율은 80%까지이며 받는 피해 증가 배율과 곱한다. 재활용 증폭기는 자기 자신의 recycle 태그를 금속으로 세지 않는다. 회피 충전은 공격 시작 시 소모하므로 명중하지 않아도 소모된다. 강화/추가 타격은 HUD 메시지로 확인할 수 있다.

탄산 과충전기는 현재 액체 시스템이 없으므로 탄환 피해 증가로 대체했다. 미구현 액체 효과가 동작하는 것처럼 표시하지 않는다. 우정의 빨대는 조건을 만족하는 동료가 없으면 효과가 없으며 싱글에서도 탐험을 정상 진행할 수 있다.

기존 스프라이트를 임시 아이콘으로 재사용했다. 최종 아이콘·아트는 교체 대상이다.

## 4. 보상 생성과 선택

1. 필수 적 처치로 라운드가 클리어되면 ExpeditionManager가 보상 상태로 진입한다.
2. 라운드의 보상 테이블 ID에 연결된 카탈로그에서 가중치 기반으로 최대 3개 후보를 생성한다.
3. 같은 선택 화면에서 중복 ID를 제외하고, 중복 정책·최대 중첩에 따라 획득할 수 없는 아티팩트를 제외한다.
4. 주입한 System.Random으로 추첨하며 시드 기반 재현이 가능하다. 게임 규칙 전체를 UnityEngine.Random 전역 상태에 묶지 않는다.
5. 후보가 부족하면 가능한 개수만 표시한다. 후보가 없으면 계속 진행하는 경로를 제공한다.
6. 선택 시 상태·선택 완료 가드로 한 번만 지급한다. 획득 중 외부 HP/빌드 콜백이 세션을 종료하거나 바꿔도 이전 선택을 새 세션으로 이어서 처리하지 않는다.
7. 획득 결과를 세션 보상 기록에 남기고 다음 경로 또는 최종 성공으로 진행한다.

UI는 후보·보유 효과를 표시하고 선택 명령을 전달한다. 후보 생성·지급 판정은 UI가 소유하지 않는다. 향후 서버에서 생성한 후보 목록과 승인된 선택 결과로 교체할 수 있는 경계다.

## 5. 보정·스냅샷·효과 수명

- 같은 보정 종류는 보유 중첩 수에 비례해 합산한다. 제한과 개별 조건은 위 아티팩트 표 뒤의 규칙을 따른다.
- 발사된 탄환은 발사 당시 피해·관통 값을 보유한다. 이후 보상을 얻어도 이미 날아가는 공격의 수치를 바꾸지 않는다.
- 확률 추가 타격은 재귀 발동하지 않는다. 이전 탐험에서 발사한 공격의 효과는 세션 버전 검사로 차단한다.
- 관통은 같은 적의 여러 Hurtbox/Collider를 별도 적중으로 중복 계산하지 않는다.
- 회피 강화는 다음 공격 시작 시 정확히 한 번 사용한다. 명중 여부와 별개로 소비되며 재회피로 충전을 추가 적립하지 않는다.
- 저체력·동료 근접·태그 보유량 조건은 현재 빌드와 유효한 플레이어 상태로 평가한다. 동료 조건은 생존·탐험 참여 상태를 확인한다.
- 보유 목록과 효과 이벤트 구독은 플레이어별로 관리하며 UI/전투 수신자의 중복 구독을 방지한다.

## 6. 종료·사망·재시작 처리

탐험 성공·실패·재시작·귀환·빌드 비활성화 시 보유와 임시 보정을 제거한다. 기본 공격력·최대 HP 같은 영구 기본값은 덮어쓰지 않는다. HP 상한이 줄면 현재 HP를 새 상한으로 제한한다.

사망 시 아직 사용하지 않은 회피 강화만 제거한다. 진행 중 생존 동료가 있다면 사망자의 보유 목록은 세션에 남지만 동료 보너스 대상이 아니다. 새 탐험은 모든 보유와 쿨다운을 초기화한다. 장비/영구 성장 시스템 자체는 이번 범위에 구현하지 않았다.

후보·기록·종료 이벤트는 [Sprint 2의 세션 관리](Sprint2.md)와 연결한다. 라운드 전환/종료 때 잔여 적과 활성 탄환을 정리하고, 이전 공격·이벤트가 새 세션에 효과를 남기지 않도록 한다.

## 7. UI와 직접 편집 위치

- 아티팩트 수치·설명·중첩·태그: `Assets/Data/Expedition/Artifacts`의 개별 ScriptableObject.
- 추첨 목록: `Assets/Data/Expedition/ArtifactCatalog.asset`.
- 라운드 보상 테이블: 라운드 정의의 Reward Table ID 및 탐험 정의의 보상 테이블.
- 보상 카드·보유 빌드·능력치 표시: `Assets/Prefabs/UI/ExpeditionUI.prefab`.
- 카드 아트·Text/TMP·테마·전체 레이아웃 교체: [UI 커스터마이징](UICustomization.md).

선택 후 보유·능력치를 즉시 갱신하고, 효과 발동 메시지를 HUD에 표시한다. 회피 강화, 관통, 확률 추가 타격, 저체력 공격 속도 효과로 단순 수치 증가 외의 전투 차이를 제공한다. 아티팩트 UI는 전투/보상 입력 정책을 공유한다.

**Bottle Game > Expedition > Rebuild Sprint 02-03 Sample**은 샘플 데이터를 기본값으로 다시 만드는 기존 메뉴다. 문서 분리로 메뉴를 변경하지 않았으며, 직접 편집한 데이터를 보존하려면 실행하지 않는다.

## 8. 확장 경계와 보류 범위

- `RoundCompleted`, `RewardSelected`, `ExpeditionEnded`와 세션의 획득·경로 기록을 외부 보상 시스템에 연결할 수 있다.
- 현재 로컬 버전은 첫 플레이어에게 라운드 보상을 지급한다. 플레이어별 RunBuild를 갖는 것과 협동 보상 배분을 구현한 것은 다르다.
- 협동 적용 시 플레이어 ID별 보상 명령·수령 승인·난수 스트림과 서버의 후보 생성·선택 검증이 필요하다. PlayerStats 객체 참조를 네트워크 식별자로 직접 보내지 않는다.
- 기존 적 AI의 Player 태그 탐색과 전투 권한·명중·사망 승인은 별도 네트워크 작업이다.
- NGO/Relay/Lobby, 영구 레벨·성장, 본격적인 인벤토리, 제작, 농장, 새 액체 연구는 구현하지 않았다. 새 네트워크 패키지도 추가하지 않았다.
- 실제 보스·허브·영구 보상은 진행 이벤트에 연결할 후속 범위다. 완성형 상점/랜덤 이벤트는 [Sprint 2](Sprint2.md)의 최소 흐름을 확장해야 한다.

## 9. 검증 기록과 남은 확인

Unity 2022.3.62f3의 분리된 프로젝트에서 실제 Play Mode로 **아티팩트 14개 시나리오를 통과**했다. 원본 실행 결과 XML은 삭제했으며 아래에 검증 요약을 유지한다.

- 획득·중첩·최대 중첩·제거 후 기본 능력치 복귀.
- 시드 기반 후보·중복 제외·획득 불가 항목 제외.
- 회피 강화 공격 한 번 적용과 소비·초기화.
- 관통과 동일 적의 여러 Hurtbox 중복 타격 방지.
- 확률 추가 타격과 이전 세션 공격의 발동 차단.
- 저체력·동료·태그 조건, 플레이어별 빌드 독립성.
- 탐험 빌드 10회 초기화 시 상태 누적 없음.
- 공격 속도 보정 후 펀치 전체 회수와 탄환 재사용 중 콜백 안전성.

초기 종합 검증은 전투 18 + 탐험 7 + 아티팩트 14 + UI 흐름 1의 40개 시나리오였다. 이후 전투 21개 회귀와 전체 UI/프리팹 교체 검증은 [Sprint 1](Sprint1.md), [Sprint 2](Sprint2.md), [UI 커스터마이징](UICustomization.md)에 연결되어 있다. 초기 40개와 후속 실행 수를 합산하지 않는다.

Unity CLI에서는 `-runTests -testPlatform EditMode -testFilter Sprint03ArtifactTests`로 묶음을 별도 실행한다. 실행 진입은 EditMode지만 내부에서 EnterPlayMode/ExitPlayMode로 실제 플레이 루프를 사용하며 완료 마커까지 확인한다. 여러 EnterPlayMode 묶음을 한 프로세스에서 실행한 표시상 통과만을 검증 근거로 사용하지 않는다.

공격·회피의 기존 동작 회귀는 [Sprint 1](Sprint1.md)의 전투 결과에, 보상 카드와 실제 탐험 진행은 [Sprint 2](Sprint2.md)의 UI 결과에 있다. 모바일 실기기 터치·한글 폰트·안전 영역·성능, 최종 아트, 수치 밸런스와 주관적인 전투 체감은 별도 검수 대상이다. 문서 재정리 과정에서 새 테스트를 실행한 것으로 기록하지 않는다.
