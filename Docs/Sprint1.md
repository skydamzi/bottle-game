## 3. 버그 수정과 상태 우선순위

총알 생성 함수는 큐에 객체를 넣지 않는다. 준비 단계와 반환 단계만 큐에 넣고, 대여 시 활성 집합에 등록한다. 활성 집합에서 제거되는 첫 반환만 유효하다. 파괴된 대기 객체는 다음 대여 때 건너뛴다.

총알은 자신의 만료 시각을 관리한다. 대여할 때 초기화하고 비활성화할 때 해제하므로 무기 오브젝트 비활성화나 이전 대여 타이머가 수명에 영향을 주지 않는다. Poolable은 프리팹에 미리 부착하되, 이전 프리팹에도 Init 시 재참조하는 방어를 둔다.

공격 상태는 PlayerAttackController가 관리한다. 자연 종료·취소·컴포넌트 비활성화에서 동일한 정리 경로를 사용한다. 종료 감시는 0.85초 이후 연출 진행이 3프레임 이상 끊긴 경우 잠금을 해제한다. 낮은 프레임률에서도 정상적으로 진행 중인 뻗기·유지·회수 연출은 시간 초과만으로 자르지 않는다. 공격 종료는 공격 상태만 정리한다.

NeckEffectController는 목의 위치·크기와 장갑 상태를 정리하며 회전은 덮어쓰지 않는다. 레거시 방향 펀치가 끝나면 PlayerAimController가 마지막 공격 각도에서 기존 rotationSpeed와 Slerp로 정면까지 부드럽게 복귀시킨다. 공용 초기화에서 회전을 강제로 원위치로 바꾸던 회귀를 제거했다.

최종 속도 우선순위: 사망 → 경직/넉백 → 회피 → 공격 이동 제한 → 일반 이동. 정지 자동 공격은 위 상태와 입력 조건을 통과한 경우에만 실행한다. 회피 무적 밖에서 피격되면 회피와 공격을 취소하고 경직을 적용한다. 무적 중 피격은 HP와 행동 상태를 변경하지 않는다.

## 4. 조작 시스템

실제 Player 오브젝트의 PlayerMovement에서 `controlMode`를 선택한다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| controlMode | 씬: SingleStickFlick / 코드: LegacyDualStick | 기존 씬의 미설정 컴포넌트는 레거시 유지 |
| acceptsLocalInput | true | 해당 플레이어만 로컬 UI를 읽도록 구성; 비소유 플레이어는 false |
| movementDeadZone | 0.2 | 이동 시작 기준 |
| proportionalSpeed | false | 단일 모드에서 입력 크기에 비례하는 속도 선택 |
| autoAttackDelay | 0.12초 | 중립 복귀 후 자동 공격 대기 |

단일 모드에서는 오른쪽 공격 조이스틱을 숨긴다. 레거시로 변경하면 같은 참조를 다시 활성화한다. 무기 전환 버튼은 유지한다. `legacyActionUI`에 추가 레거시 전용 UI를 지정할 수 있으며 무기 전환 버튼은 넣지 않는다.

PlayerMovement만 Rigidbody2D 속도를 적용한다. 회피 컨트롤러는 방향과 속도를 제공한다. 고속 이동 전 일반 발 콜라이더로 Cast하고, Trigger는 장애물 검사에서 제외한다. 콜라이더를 끄거나 Transform 위치를 순간 이동시키지 않는다.

## 5. 플릭 판정과 한계

1. 실제 PointerDown이 조이스틱 입력 크기 0.2 이하인 중앙에서 시작해야 한다.
2. 같은 포인터의 후속 Drag에서 0.12초 이내에 입력 크기 0.85 이상, 화면 이동 12px 이상에 도달해야 한다.
3. 터치 한 번당 한 번만 판정한다. 방향을 바꾸거나 다시 중앙으로 이동해도 손을 떼기 전에는 재무장하지 않는다.
4. PointerUp, TouchPhase.Canceled, 비활성화, 앱 포커스 상실·일시정지는 플릭을 만들지 않는다.
5. 다른 손가락의 입력은 활성 조이스틱 포인터를 빼앗거나 해제하지 못한다.

`flickEnabled`, `reachThreshold`, `maxFlickTime`, `minimumDragPixels`로 활성 여부와 민감도를 조절한다. `logFlicks`를 켜면 판정 방향과 시간이 출력되고, 실행 중 `debugStatus`를 Inspector에서 볼 수 있다. 실제 회피가 승인되면 플레이어 색상을 잠시 바꾼다.

중앙에서 빠르게 끝까지 미는 일반 이동과 플릭은 동일한 물리 입력일 수 있어 완벽한 구분은 불가능하다. 이번 정책은 중앙 시작 + 짧은 드래그 + 터치당 한 번으로 오발동을 줄인다. 바깥쪽을 바로 누르는 이동은 회피하지 않는다. 이미 누른 채 중앙에서 다시 미는 동작은 새로운 플릭으로 인정하지 않는다. 같은 프레임에 시작·종료하는 초단기 터치는 시간 이력이 부족해 누락될 수 있다. 12px 기준은 기기 DPI별 튜닝이 필요하다.

| 회피 설정 | 기본값 |
|---|---:|
| cooldown | 시작 기준 0.5초 |
| duration | 0.3초 |
| distance | 장애물 없을 때 2.5 units |
| invulnerableStart / End | 0.05 / 0.25초 |

무적은 물리 틱 시각 기준이며 종료 경계는 포함하지 않는다. 회피 시간과 거리는 시작 시 고정한다. 벽에 막히면 이동 거리가 줄어든다.

## 6. 자동 공격·조준

중립 지연 경과, 생존, 경직·회피 없음, 로컬 입력 허용, 사거리 내 유효 대상 조건을 검사한다. 대상이 없으면 공격하지 않는다. 이동이 시작되거나 플릭 회피가 승인되면 충전·실행 중인 주먹을 안전하게 취소한다. 이미 발사된 총알은 정상 수명을 유지한다.

PlayerAutoTarget은 기본 0.1초 간격으로 Monster 레이어의 Collider2D를 조회한다. 64개 버퍼를 재사용하고 포화 시에만 전체 결과 배열을 얻는다. IDamageable과 MonsterStats가 있고 활성·생존·사거리 조건을 만족하는 가장 가까운 본체를 고른다. 현재 대상은 매 호출 시 유효성을 재검사한다. 타겟 선택과 실제 무기 실행을 분리했으며 부위 타겟팅은 추가하지 않았다.

현재 기본 사거리는 총 2, 주먹 1.5 units다. 초기 총 사거리 8은 후속 수정에서 2로 줄였다. 현재 몬스터 루트 위치를 기준으로 거리·조준을 계산하며 장애물 가시선 검사는 이번 범위에 포함하지 않는다. 실제 판정 크기와 보스 크기에 맞춰 Inspector에서 사거리를 조정해야 한다.

총은 기존 0.1초 간격으로 Gun을 호출한다. 자동 주먹의 `autoFistChargeTime` 기본 0은 충전 비율 0의 최소 공격이다. 값을 늘리면 기존 maxChargeTime 범위에서 자동 충전한다. 데미지는 기존 `attackDamage * (1 + ratio)` 그대로다.

자동 주먹은 뻗기 → 유지 → 회수 전체가 끝난 뒤에만 다음 공격을 시작한다. 공격 중 타겟이 죽거나 비활성화되거나 사거리 밖으로 나가더라도 진행 중인 펀치를 즉시 초기화하지 않는다. 타겟 탐색은 PlayerAutoTarget에서 독립적으로 계속 수행하지만, 실행 중인 펀치의 발동 방향과 회수 동작은 유지한다. 회피·피격·사망·명시적인 이동 취소는 기존 취소 규칙을 유지한다. 별도의 반복 간격 제한은 추가하지 않았다.

## 7. 레거시 호환성과 이벤트

LegacyDualStick은 왼쪽 이동, 오른쪽 조준·연사/충전·해제 공격을 유지한다. 정규화된 기존 이동 속도와 무기별 데미지·타이밍 설정을 유지한다. Sprint 1 초기 전투 작업에서는 MainMenu 씬을 변경하지 않았다. 이후 UI 변경은 [모바일 UI](MobileUI.md)와 [UI 커스터마이징](UICustomization.md)에 기록한다.

레거시 주먹 실행 중에는 발동 당시의 몸 방향과 병목 조준 방향을 유지한다. 왼쪽 이동 스틱을 바꾸더라도 LastMoveDirection과 Animator InputX/InputY를 갱신하지 않는다. 입력 자체는 계속 수집하므로 회수가 끝나면 현재 누르고 있는 방향으로 이동과 방향 갱신을 재개한다. 충전 중 이동 및 단일 모드의 이동 취소 정책은 유지한다.

이벤트의 발신 PlayerStats를 구독자가 자신의 PlayerStats와 비교한다. 구독은 OnEnable/OnDisable에서 대칭 관리한다. 인스턴스 이벤트로의 전환도 검토했지만, 이번에는 기존 static 클래스와 호출 위치를 유지하면서 발신자만 추가하는 변경을 선택했다. 모든 프로젝트 호출·구독 코드를 함께 변경했다. 외부 코드가 있다면 이벤트 시그니처에 발신자 인자를 추가해야 한다.

공격 상태는 이벤트 수신으로 변경하지 않고 각 공격 컨트롤러가 직접 소유한다. 초상화나 다른 플레이어가 외부 공격 이벤트만으로 공격 실행 상태에 들어가지 않는다.

| 사거리 밖 대기, 가장 가까운 유효 적, 이동 중 자동 공격 중단, 0.1초 연사 하한 | 통과 |

원본 NUnit 실행 결과 XML은 정리 과정에서 삭제했으며 위 표에 검증 요약을 유지한다. 씬·총알 프리팹의 기존 직렬화 오브젝트와 참조가 삭제되지 않은 점, 새 패키지가 없는 점, diff 공백 오류가 없는 점도 확인했다.

## 9. Editor·모바일 추가 검증 절차

자동화 테스트는 합성 PointerEventData와 실제 2D 물리를 사용한다. 사람이 Editor 화면에서 조작하는 검사, 실제 OS 멀티터치·터치 취소, 모바일 빌드/실기기 평가는 별도로 수행해야 한다.

1. SampleScene을 열고 SingleStickFlick에서 중앙을 천천히 밀어 이동, 중앙을 빠르게 밀어 회피, 바깥을 바로 눌러 이동, 놓기·방향 전환 시 회피 없음 확인.
2. 적 근처에서 놓고 0.12초 이후 공격, 사거리 밖에서 대기, 총↔주먹 전환, 자동 충전값 0/0.2/0.8초 비교.
3. 자동 주먹 실행·충전 중 이동과 플릭으로 취소. 총을 쏜 직후 주먹으로 바꿔 빗나간 총알이 1초 뒤 반환되는지 확인.
4. 얇은 벽·모서리·타일맵·이동 장애물에 상하좌우·대각선 회피. 콜라이더 유지와 벽 관통 없음 확인.
5. 공격 중 Player 또는 NeckEffectController를 비활성화·재활성화하고 이동·주먹 판정·목 스케일 복구 확인.
6. 플레이어 둘을 배치하고 각각 다른 UI를 연결. 한쪽 acceptsLocalInput=false에서 다른 쪽 입력으로 이동·공격·연출이 실행되지 않는지 확인.
7. LegacyDualStick으로 바꾸고 오른쪽 UI 복원, 기존 충전·해제 공격과 이동 확인.
8. Android/iOS 실제 기기에서 이동/플릭/터치 취소/멀티터치/백그라운드 복귀를 각각 반복. 앱 복귀 시 입력과 무적이 남지 않는지 확인.
9. 30/60/120fps와 서로 다른 DPI·화면 비율에서 일반 이동 50회, 의도한 플릭 50회, 이동 중 방향 전환 50회를 수행. 오발동·누락 횟수와 자동 공격 체감 지연을 기록하고 threshold/time/pixels를 조정.

Sprint 1 초기 입력 작업에서는 화면 방향·Canvas 스케일을 유지했다. 이후 Safe Area와 모바일 Canvas 배율을 적용한 내용은 [모바일 UI 정리](MobileUI.md)에 있다. 실제 모바일 기기의 터치·안전 영역·성능 검증은 여전히 별도 확인 대상이다.

## 10. 향후 NGO 고려사항

- `acceptsLocalInput`은 입력 분리용 설정이며 네트워크 소유권 검증을 대신하지 않는다. 소유권 획득·상실 시 설정과 UI 연결을 갱신해야 한다.
- 현재 이벤트의 PlayerStats 참조를 네트워크 식별자로 직접 직렬화하지 않는다. 이벤트 전달과 네트워크 메시지를 구분한다.
- 데미지 승인·회피 무적·명중·사망의 최종 권한과 서버 시각을 정해야 한다. 현재 로컬 타이머와 Trigger 판정을 그대로 양쪽에서 승인하면 안 된다.
- 투사체 풀 대여/반환과 네트워크 Spawn/Despawn을 연결하고 발사·공격별 식별자를 도입해야 한다.
- 몬스터의 기존 Player 태그 추적, 카메라·UI 소유권, 대형 보스의 조준 지점·부위별 중복 명중 정책은 별도 작업이다.

기존 사용자 변경인 Portrait_RT.renderTexture, .vsconfig, ProjectSettings/Packages는 보존한다.

## 11. 후속 전투 개선 기록

아래는 수정 당시의 기록이다. 현재 총 사격에는 병목 정렬 대기 조건이 없으며, 총/주먹 사거리는 2/1.5다. 펀치는 조준 정렬·발동 방향 고정·전체 회수를 유지한다. 중간 단계의 규칙은 뒤의 최종 수정 기록으로 대체된다.

### 후속 수정: 자동 조준 회전 (2026-10-21)

PlayerAimController의 SetAutoTarget과 단일 스틱 LateUpdate에서 목표 회전을 즉시 대입하던 처리를 제거했다. 타겟 획득·변경·해제 시 기존 rotationSpeed와 Quaternion.Slerp로 회전한다. PlayerAttackController의 자동 펀치는 실제 병목과 목표 방향의 차이가 1도 이내가 된 뒤 발동한다. 레거시 입력 분기와 펀치 발동 방향 고정·회수 처리는 유지한다.

기존 전투 묶음에 자동 조준 획득/반대편 전환/타겟 해제의 중간 회전과 펀치 조준 대기 검사를 추가했다. Unity 실제 Play Mode에서 전투 19개 시나리오 및 UI 전체 흐름 검사가 통과했다. 초기 Sprint 2–3 통합 검증은 전투 18 + 탐험 7 + 아티팩트 14 + UI 흐름 1의 40개 시나리오였으며, 후속 검증과 합산하지 않는다.

수동 확인: SampleScene Play → 탐험 시작 → 이동해서 적이 플레이어 옆에 오도록 한 뒤 이동 스틱에서 손을 뗀다. 병목이 적 쪽으로 부드럽게 돌아가는지 확인한다. 무기를 펀치로 전환해서 조준 후 발동하고, 발동 방향을 유지한 채 끝까지 회수하는지도 확인한다. 회전 속도는 실제 Player의 PlayerAimController → Rotation Speed 기존 값을 사용한다.

### 후속 수정: 상시 타겟 추적 및 표시 (2026-10-21)

- PlayerAutoTarget이 단일 스틱의 로컬 생존 플레이어 타겟을 독립적으로 갱신한다. 이동·중립 대기·공격 쿨다운·회피 중에도 사거리 내 적을 추적한다. 사망/비활성화/사거리 이탈은 즉시 유효성을 해제하고 다른 후보를 찾는다. 기본 최근접 선택 규칙은 유지했다.
- PlayerAimController는 이 타겟을 읽어 보간 회전한다. PlayerAttackController는 타겟을 해제하지 않고 이동/중립 대기/피격/회피와 실제 조준 정렬을 발사 조건으로 검사한다. 자동 총알도 병목이 조준되기 전에 발사하지 않는다. 펀치 실행 중 발동 방향 잠금과 전체 회수는 그대로다. 단일 스틱 무기 전환 시에는 병목을 정면으로 순간 초기화하지 않는다.
- 새 PlayerTargetingView는 읽기 전용 표시 계층이다. 선택 적 머리 위 노란 삼각 화살표와 플레이어 중심의 청록색 사거리 테두리를 LineRenderer로 그린다. 충돌체·피해 판정·타겟 검색·UI 입력 처리가 없고, 생성한 선/머티리얼은 플레이어 제거 시 함께 정리한다. SampleScene 실제 Player에 연결했으며 에디터 샘플 설치 코드도 연결을 유지한다.
- ExpeditionUI 상단에 타겟 이름, 거리, 현재 유효 사거리, 타겟 없음/대기 상태를 표시한다. HUD는 입력을 차단하지 않는다. 사거리 계산은 무기와 아티팩트 효과를 포함한 PlayerAutoTarget.GetRange를 공유하므로 UI와 원 크기에 별도 수치를 복제하지 않는다.

설정 위치: 실제 Player → PlayerAutoTarget의 Gun Range/Fist Range가 게임 규칙이며, PlayerTargetingView의 Show Range/Show Target Marker/색상/선 두께/Marker Offset은 표시 설정이다. 이 수정 당시 총 사거리 8은 orthographic size 5인 세로 카메라 시야보다 크므로 원 테두리가 화면 밖에 있을 수 있다. 실제 거리 표시를 위해 원을 임의로 축소하거나 카메라/사거리를 변경하지 않았다. 펀치 사거리 1.5는 가까운 원으로 확인할 수 있다.

검증은 전투 20개 시나리오와 실제 씬 UI 통합 흐름이다. 이동 중 추적과 발사 금지, 중립 대기 중 조준 유지, 정렬 전 총알 발사 금지, 화살표의 실제 타겟 위치, 아티팩트 사거리 변경, 사망 후 다른 타겟 재선정, 타겟 없음/입력 정지/레거시 모드의 표시 해제, 상단 텍스트와 실제 타겟 일치, EventSystem 입력 통과를 확인한다. 모바일 실기기에서 선 두께·색상·카메라 구도는 수동 검수 대상이다.

이후 기본 총 사거리를 8 → 2로 줄였고 코드 기본값과 SampleScene 값을 함께 변경했다. 펀치 사거리는 1.5다. 카메라 orthographic size 5 기준 9:16과 9:20 세로 화면의 가로 반폭은 각각 약 2.81, 2.25이므로, 플레이어를 중심으로 기본 반지름 2의 원이 들어온다. 사거리 아티팩트로 강화되거나 카메라가 이동을 따라가는 순간에는 테두리가 화면 밖으로 나갈 수 있다. 장거리/배율 테스트는 해당 테스트 안에서 사거리 8을 명시하고, 실제 씬 UI 테스트는 적이 새 사거리 안으로 접근할 때까지 기다리도록 조정했다. 이 수치 변경 후 Play Mode 재실행은 하지 않았다.

### 후속 수정: 사거리 안에서 자동 총 발사 (2026-10-21)

자동 총 사격에 공통으로 적용했던 병목 회전 오차 1도 조건을 제거했다. 현재 규칙은 **정지 대기 완료 + 사거리 내 유효 타겟 + 기존 쿨다운**이다. 사망·피격 경직·회피·입력 차단·이동 중에는 기존처럼 발사하지 않는다. 총알은 선택 타겟의 실제 위치를 향해 발사하고, 병목은 기존 방식으로 부드럽게 회전한다. 레거시 수동 사격은 기존 병목 방향을 사용하며, 펀치의 조준 대기·발동 방향 고정·전체 회수는 유지했다. 사거리 값은 총 2, 펀치 1.5 그대로다.

PlayerAttackController의 기존 HandleGunAttack에 자동 타겟 인자만 선택적으로 전달하여 Gun의 공개 인터페이스·풀·입력·타겟 선택 구조를 유지했다. 회전 보간은 총 발사 가능 여부를 결정하지 않는다. 앞선 기록의 ‘정렬 전 총알 발사 금지’는 이 변경으로 대체된다.

새 회귀 검사는 적이 실제 사거리 2 안의 거리 1.9를 유지한 채 움직일 때 반복 사격하는지, 탄환 초기 방향이 선택 타겟을 향하는지, 실제 물리 충돌로 피해가 발생하는지, 거리 2.1에서는 새 발사를 멈추는지 확인한다. 기존의 20개 시나리오와 실제 씬 UI 통합 검사를 함께 실행했다. 이 후속 검증은 위의 사거리 변경 후 Play Mode 재실행도 포함한다.

최종 결과: Unity 2022.3.62f3의 실제 Play Mode에서 전투 21개 시나리오와 실제 씬 UI/물리 전투 통합 검사가 모두 통과했다. 테스트 복사본과 작업 폴더의 런타임/씬 파일 일치도 확인했다.
